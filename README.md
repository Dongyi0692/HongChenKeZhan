# 风尘客栈

Unity 可编辑工程。使用 Unity Hub 添加本文件夹，编辑器版本为 **Unity 6.3 LTS（6000.3.25f1）**。打开 `Assets/_Game/Scenes/InnDuel.unity`，在 Unity 中点击 Play。

项目中的大文件通过 Git LFS 保存。请安装 Git LFS 后再克隆，或在已有克隆内执行 `git lfs pull`。

当前版本包含主角、小兵、精英及客栈场景。WASD 跑步，鼠标调整视角，Space 跳跃，Shift 闪避，Q 格挡，鼠标左右键轻击与重击，F 技能，E 交互。

## 战斗改进分支（2026-11-16）

`combat-improvements` 是独立战斗分支。原客栈场景、人物资源、家具及碰撞体不在本次修改范围；新行为由已有脚本自动生效，不需要重建场景或重新安装角色。

- 轻重击与技能起手时，在人物前方及镜头内选择近处敌人，短暂辅助转向；目标被遮挡、离开范围、倒地或转为友军后释放，不在同一次出招中改选其他目标。
- 敌人身上的小方框与敌人血条对应同一目标。真实命中、攻击被格挡、成功防御及自己受击有独立短提示与低音量声音。
- 最后一段伤害窗口结束后，轻击保留约 0.12 秒、重击约 0.18 秒、技能约 0.16 秒的收势代价，之后可主动移动、格挡或接下一动作。不输入时继续播放完整收势。重击四式伤害窗口均保留。
- 跑步不耗体力；跳跃、闪避、格挡保留体力规则。格挡会优先于此前缓存的进攻输入。
- 镜头避障忽略战斗角色，仍受墙、柱、家具限制；没有增加攻击变焦。
- 普通小兵倒地 4 秒后隐藏，重试恢复；精英追兵保留胜后转友军的剧情。

队友提交场景后，先提交自己的战斗改动，再将最新 `main` 合并到本分支，在她的新场景上检查楼梯、碰撞、目标与攻击。不要用旧工程的整个 Assets 文件夹覆盖她的新版本；如同一场景有双方修改，逐项保留新场景布局和必要的战斗引用。

三段战斗支持本段重试：教学小兵、追兵决斗、回援并肩战分别记录开战起点。失败界面的“重试本段”和 R 键恢复当前段，跳过战前对白，保留前段胜利；战斗中 R 也重试当前段。主角满生命、满体力并清除动作和技能冷却；本段敌人恢复满生命，回援段的友军追兵恢复该段开战生命。沿用已有角色，不重复生成来兵。失败尝试的战斗用时不计入最终用时。探索时 R、回到标题以及通关后的“再玩一次”仍从整局开头开始；本段检查点仅在本次游戏运行期间保留。

分段重试验证已通过：现有 InnDuel 场景中三段各失败并重试两次，100 项检查通过，包括实际失败界面按钮、R 共用入口、角色与阵营恢复、前段胜利保留、敌人不重复生成、重试后继续获胜和回标题重开。Unity 编译及运行日志无错误；失败界面文字已截图检查。验证脚本 `Assets/_Game/Editor/StageRetryVerification.cs` 通过真实伤害接口触发剧情转换，暂时停用 AI 更新以隔离检查流程，不代替动作命中或难度评测。报告和截图位于本机 `Logs/StageRetryVerification.json`、`Logs/StageRetryDefeat.png`，未保存或改动场景。

验证入口在 `Assets/_Game/Editor/CombatFeelVerification.cs` 和 `CombatFeelPlaythrough.cs`。组件规则检查与实际动画试玩分别记录；后台报告位于被 Git 忽略的 `Logs` 目录，运行结果不等于人工手感验收。

本轮验证：Unity 6000.3.25f1 编译通过，39 项组件与碰撞规则检查通过。在现有 InnDuel 场景中，以真实角色、动画和武器碰撞运行了约 4.8 秒的受控战斗：每招只请求一次，起手辅助转向 25°，轻击命中 1 次、重击命中 4 次，轻击收势接格挡与重击收势接闪避通过，无运行错误。测试临时关闭了敌人 AI 并提高其血量，以隔离检查命中和衔接；尚未替代真人完整流程、多人协作合并后新场景的碰撞及手感验收。主场景文件未修改。
