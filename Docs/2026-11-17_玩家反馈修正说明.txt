红尘客栈｜2026-11-17 编辑版 v4 玩家反馈处理说明

交付：更新当前完整 Unity 可编辑工程；本轮不生成 exe、不生成 ZIP、不上传 GitHub。新改动须在 Unity 内 Play 体验，旧 v3 独立程序不包含本轮修改。

1. 重击与F相似、按键容易混淆
原因：原右键动作是约4.33秒的四段重击；原F动作是约1.57秒的单次突进斩，本来不是同一个动画，但名称和提示没有把用途讲清。
修改：交换绑定，F四式重击、右键突进斩（成功起招30体力、无冷却）；同步实操教学、战斗提示、常驻操作表与暂停说明。保留各自动作和命中窗口，不为了交换按键而交换伤害/体力规则。

2. 镜头像第一/第三人称来回变、敌人容易出画
原因：原系统以自由视角和攻击起手辅助为主，没有持续锁定；近墙避障收近与侧移会改变主体比例。新增锁定初测又发现把相机支点推向两人中间会让主角出画，已据实机失败定位并修正。
修改：鼠标继续自由转镜头；中键锁定/解除、Tab换敌。相机绕主角肩部保持跟随，观察方向照顾双方；避免墙体时优先可用的第三人称距离并限制侧转跳变。死亡、过远或持续隔墙解除锁定。狭小空间仍以不穿墙为先，不能保证任何墙角都有理想构图。

3. 战斗像“各打各的”、想要格挡变化与打断
原因：真实受伤原来已有中断出招，但长按格挡缺少时机奖励；多人战的目标选择未优先回应实际打中自己的人。
修改：迎面±55度、抬起格挡0.18秒内命中为精准格挡，打断攻击者并造成0.55秒硬直，挡中体力消耗降为普通的35%。普通格挡保留，侧后攻击不能精准格挡；防止快速反复点按刷新窗口。敌人受伤后2秒优先反击有效攻击来源，避免隔墙/不同楼层追错目标。攻击转向优先当前锁定敌人，但剑长、真实命中与遮挡限制保留。

4. 跑步挥臂生硬、持剑穿过自己
原因：跑步素材来自徒手冲刺，直接握剑会把剑带过躯干；动作风格偏大。性别化观感是审美意见，不是可以由代码断定的错误。
修改：保留已有右手持剑稳定，本轮额外把左臂摆动温和收敛，保留原动作35%和小幅随步节奏。只调整手臂旋转，不缩放骨骼、不冻结躯干、不改腿部与挥剑片段。挥剑仍需要转腰、重心与收势；没有采用“攻击时整个身体不动”的建议。
限制：未定位到可直接证明攻击蒙皮撕裂的代码错误；本轮没有重绑模型或改权重。抽查动作截图不能证明所有姿势无穿插，精英护裙等大幅动作的蒙皮仍是后续需修的资产问题。

5. 操作忘记、暂停找不到帮助
修改：右下常驻操作简表，F1随时查看；暂停菜单增加操作说明，关闭说明返回暂停。首次截图发现末行裁切，已修正文字区并复查真实布局。

6. 找不到下一步、在楼上绕圈
原因：目标主要是文字提示，缺少相对方向；其中“找后门”的反馈来自旧流程，当前第三战已经改为前门入堂。
修改：当前前门/账本/门边交谈增加方向、距离与楼上楼下提示。战斗时隐藏导航条，避免遮挡。保留室内第三战，不添加失效的后门任务。

7. “更有想象力”和作品表达
这是设计方向意见，不能据此随意增加系统。用新稿明确红拂自主离开、斗笠客误会与释疑、并肩迎敌后的结交；AI资产与制作说明继续保留。没有新增场景、特效或偏离现有体验的大系统。

8. 新剧本接入
源稿已完整保存在 Docs/Story，并提取295段供核对。角色仍为红衣；运行文本无紫衣。精英在报名前称斗笠客，结尾自报虬髯客；小兵一直敌对。
保留玩法流程：入栈→账本→实操→小兵战→斗笠客决斗→五兵从前门入堂并肩战→自动结交结算，三段失败各重试本段、每段开战满血。
冲突：不新增序言、后门离开再返回、清敌后按E再次交谈、走出后门才结算及新短句触发系统。相关台词移到现有节点。完整11项与源稿段号见 Docs/Story/2026-11-17_新稿接入与流程冲突.txt。

本轮验证记录已写入 README 的“编辑版 v4 验证”段：编译、动作/文本25项、UI19项、格挡/还击16项、锁定50帧双方全部可见，以及五兵入堂的真实AI联战、自然胜利到新结尾均通过；运行错误0。最终动作观感、难度与硬件键鼠体验仍需用户试玩，不把自动检查称为人工审美验收。
